## 1. 개요

사진 분석과 AI 원고 생성 **사이에 "계획 검수" 단계**를 추가했다. 프로그램이 `Day → 장소 → 사진` 초안을 자동 생성하면, 사용자가 장소명·일정·사진·사건/느낌·별점·영수증(가격)을 확인·수정한다. 확정된 계획(`plan.json`)이 **생성의 단일 진실원**이 되며, 프로젝트 불변식 **"형식은 코드가 조립, AI는 본문만"** 을 지킨다.

**핵심 원칙**: 지도·별점·가격 등 형식은 코드가 조립하고, 사건/느낌/지시 등 재료만 AI에 전달한다. **발행 HTML에는 어떤 URL/지도도 넣지 않는다**(네이버 SE3가 링크카드로 변환해 망가짐). 지도는 검수 화면(내부 도구)에서만 보여준다.

## 2. 최종 5단계 워크플로우 (단계별)

```
1. 업로드 → 2. 계획 검수 → 3. AI 생성 → 4. 편집 → 5. 발행
```

### STEP 1 · 업로드
- **📷 여행 사진** 드롭존 + **🧾 영수증** 드롭존(분리). 영수증은 올리는 즉시 OCR(가게명·금액·날짜) → `state["receipts"]`.
- "분석 시작" → EXIF GPS·Vision 분석.

### STEP 2 · 계획 검수 (핵심)
- 상단: **무료 모드 배너**(상호명 정확도 낮음, 검수 권장), 접이식 "여행 설정(제목·참고 URL)".
- **Day별 카드**: 각 장소(stop)마다
  - 장소 이름(자동 확신시 채움, 무료모드면 빈칸)
  - **사진 썸네일(112px, 클릭 확대)** + 💬 장면설명 힌트
  - **인라인 지도**(OSM 핀) + "📍 구글 지도에서 열기"
  - 📝 무슨 일이 있었나 / 💭 느낀 점 / ✍️ AI 지시 / ⭐ 별점
  - **🧾 영수증**: 업로드 단계 영수증이 가게명↔장소명(+날짜)으로 자동 매칭돼 표시, "장소 변경" 드롭다운으로 재배정. 상단 "미배정 영수증" 칸에서 수동 배정.
  - **수동 묶기**: "🔗 다른 장소와 합치기" 드롭다운, 썸네일 "✂ 분리"(새 장소로).
- **자동 저장**(입력시 디바운스) + **💾 수동 저장** 버튼.
- 오른쪽: **게시물 구조 개요**(Day별로 제목→인트로→장소(사진·요약)→이동→팁→마무리).

### STEP 3 · AI 생성
- 글 스타일 선택.
- **📅 날짜별 일정 목록** — Day별 장소·사진수 표시, 클릭해 선택.
- "✨ 선택한 Day만 생성" / "🚀 전체 일정 생성". 실패 시 원인 팝업.
- 오른쪽: 게시물 구조 개요.

### STEP 4 · 편집
- Day 탭 전환, 블록(텍스트/이미지/구분선/라벨/경로) 편집, 초안 선택.
- 오른쪽: **실제 완성 글 미리보기**(위키박스·경로·별점/가격 줄 포함).

### STEP 5 · 발행
- 제목·태그·발행방식·공개설정.
- "📤 발행"(현재 Day) / "🚀 전체 일정 한번에 발행"(확인창 후 Day별 각각).

## 3. 진행 내역 (구현 순서)

### 3.1 계획 검수 코어 (백엔드, 순수함수 TDD)

- `app.py`: `plan.json` 영속화, `/api/plan*`(draft/get/post/이동/제외/영수증), `/api/receipts/upload`, `/api/photos`에 `pid` 추가, `_active_groups`(plan→Day그룹). 생성 라우트가 plan 사용.

### 3.2 검수 UI (프론트, `static/index.html`)
- 2단계를 "계획 검수"로 교체(렌더·편집저장·영수증·매칭·썸네일·지도·묶기).
- 3단계 Day 목록, 5단계 전체 발행 버튼, 오른쪽 구조 개요.

### 3.3 UX/시각
- 테마: 부드러운 상아색 + 연두(`:root` 팔레트).
- 카드 시각 정리(썸네일 크게·필드 라벨/예시·여백).

### 3.4 자가 QA & 버그 수정

## 4. 문제사항 & 해결 (중요)

| # | 문제 | 원인 | 해결 |
|---|---|---|---|
| P1 | 검수 UI가 실제 앱에 안 보임 | `app.py`가 **`static/index.html`** 서빙인데 UI 작업을 **루트 `index.html`**(미서빙)에 함 | static/index.html로 포팅. CLAUDE.md의 "index.html" 표기가 모호 |
| P2 | 웹 UI 전체가 안 돎(정적 스켈레톤만) | `static/index.html` 인라인 스크립트에 **짝 없는 `}`**(updateSettingsPreview) → SPA 통째로 파싱 실패 (**기존 버그**) | `}` 제거. `node vm.Script`(=V8)로 파싱 검증 도입 |
| P3 | 검수 카드가 빈칸만·사진 안 보임 | 카드가 "사진 N장" 텍스트만, photo_id 매칭 불가 | `/api/photos`에 `pid` + 썸네일·💬장면힌트 표시 |
| P4 | 미배정 영수증 글자 세로 깨짐 | flex 행에서 긴 옵션 `<select>`가 최소너비 키워 `<span>` 0폭 | 세로 스택 + select `max-width` |
| P5 | 영수증 첨부 위치 못 찾음 | 카드마다 밋밋한 file input | 업로드 단계로 이동 + 자동 매칭(사용자 선택) |
| P6 | **편집(4단계) 화면 전체 크래시** | `renderS4`가 프론트에 없는 전역 `state` 참조(`state?.group_states`) → ReferenceError → 렌더 중단 (**생성 후 편집 불가, 치명적**) | `i<=curGroup`로 대체 + 초안 자동 로드 |
| P7 | "초안 생성 안 됨" | 실제 생성 실패해도 `startPoll` 콜백이 **done만 처리** → 조용히 사라짐 | error·빈 초안 시 원인 팝업. (OpenAI 키·모델은 정상 확인) |
| P8 | 프로필 불러오기 멈춤 | `/api/profiles/<name>` 함수 인자 `n`↔`name` 불일치 → **500** (**기존 버그**) | `n`→`name`. `⚙️설정`이 프로필선택(-1) 아닌 **설정화면(0)** 열도록 |
| P9 | 3단계에 날짜별 분리 없음 | Day 선택 UI 부재("현재 선택"만) | 3단계에 **Day별 목록(선택)** 추가 |
| P10 | 시드 서버 혼동 | 여러 포트에 서버 남으면 SO_REUSEADDR로 옛 서버 응답; Chrome이 5060/5061(SIP) 차단 | 재검증 전 `taskkill //F //IM python.exe`, 8088+ 안전 포트 |

**공통 교훈**: 인라인 `<script>`는 구문 OK여도 **런타임 미선언 참조/에러 무처리로 "조용히" 죽는다.** 유닛/코드리뷰로 부족 → `/browse`로 각 단계 실제 렌더 + **실제 생성 E2E**까지 확인. (자세히 `.claude/rules/lessons-learned.md` 항목 5~9)

## 9. 주의사항 (불변식·지뢰)

1. **서빙 파일은 `static/index.html`** (루트 `index.html` 아님). UI 작업은 여기서.
2. **발행 HTML에 URL/지도 금지** — 지도는 검수 UI에만. 별점·가격도 코드가 조립(URL 없음).
3. **인라인 스크립트 검증**: `node -e "new (require('vm').Script)(scriptSrc)"`(V8=브라우저). 프론트/백엔드 전역명 겹침(예: `state`) 주의 — 조용히 죽는다.
4. **되돌리기 어려운 외부작업**(전체 발행 등)은 `confirm()` + 안전 기본값(공개설정=비공개).
5. **cp949 콘솔**: `logger`/`print`에 이모지 금지(HTML 출력 문자열은 무방).
6. **재검증 전 서버 정리**: `taskkill //F //IM python.exe`, 안전 포트(8088+).

## 10. 데이터 흐름

```
[STEP1 업로드]  📷 사진               🧾 영수증
      │ /api/upload → analyze          │ /api/receipts/upload → ReceiptReader.read(Vision OCR)
      ▼                                ▼
photo_results[]                        state["receipts"][]
 (file_path, gps, location_name,        (store_name, amount, currency,
  name_confident, scene_description,     date, image_path)
  day_date, thumbnail via /api/photos)
      │
      │ POST /api/plan/draft
      ▼
TripPlanner.build_draft(photo_results)  →  plan (TripPlan)
   plan.days[ stops[ name, name_source, photo_ids[], events[], feeling,
                     ai_instruction, rating, receipt, show_* ] ]
   + TripPlanner.match_receipts_to_stops   (영수증 가게명 ↔ 장소명 + 날짜)
      │
      │ [STEP2 검수] 사람이 수정 (자동/수동 저장) → plans/<title>/plan.json  (단일 진실원)
      ▼
_active_groups() = TripPlanner.groups_from_plan(plan, photo_results)
   Day별 그룹: 확정명 덮어쓴 사진 복사본 + place_memos(사건/느낌/지시) + place_meta(별점/가격)
      │
      │ [STEP3] POST /api/generate(gi) / generate_all
      ▼
TravelBlogGenerator.generate_drafts
   _build_prompt(재료=place_memos) → _call_ai(본문 JSON)
   → _insert_photos_with_map(사진·경로) → _insert_meta_lines(별점·가격 <p>, URL 없음)
      ▼
group_states[gi].drafts → blocks → [STEP4 편집] → [STEP5 발행] /api/publish(_all)
```

**불변식 위치**: 위키박스·경로·별점·가격·지도는 전부 **코드가 조립**. AI에는 `place_memos`(텍스트)만. 발행 HTML에 URL 없음. 지도는 STEP2 검수 UI에만.
