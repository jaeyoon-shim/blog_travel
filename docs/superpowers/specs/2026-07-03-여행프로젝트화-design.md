- 날짜: 2026-07-03
- 배경: 사용자 명시 지시 "일정 하나하나가 새 프로젝트처럼 관리되어야해". 혼입 버그(`4c50db8`)는 수정됐으나, 여행 간 **전환·복귀·보존**이 불가(새 여행 시작 시 이전 여행이 UI에서 사라짐).
- 사용자 결정: 프로젝트 선택 UI = **상단 바 셀렉터 + [새 여행] 버튼**.
- 상태: 설계 확정 → writing-plans

## 1. 접근 — 최소 침습 "스왑 계층"

전역 `state` 구조는 그대로 두고(= 현재 열린 프로젝트 1개), **프로젝트 저장/로드(스왑) 계층**만 추가한다. 모든 기존 라우트·UI는 무변경으로 동작.

| 대안 | 판단 |
|---|---|
| **A. 스왑 계층** (state=현재 프로젝트, 파일로 저장/로드) | ✅ 채택 — 기존 코드 무변경, 리스크 최소 |
| B. 모든 라우트에 project_id 파라미터 | ✗ 전면 리팩터, 과대 |
| C. 프로젝트 홈 화면 | ✗ 사용자 결정으로 배제(상단 바 선택) |

## 2. 저장 구조

```
plans/<폴더명>/
  plan.json            (기존 — 계획)
  drafts/group_*.json  (기존 — 초안, G1)
  project.json         (신규 — 세션 스냅샷)
```

`project.json` 스키마:
```json
{
  "photo_paths": [...], "photo_results": [...],
  "naver_analysis": {...}|null, "style_analysis": {...}|null,
  "receipts": [...], "published_gis": [0,1],
  "completed": [1,2,3], "saved_at": "2026-07-03T20:00:00"
}
```
- **photo_results 포함 = 재분석 없이 복귀** (사진 파일은 uploads/ 공유 — photo_results의 경로 참조로 충분, 충돌은 기존 타임스탬프 접미사 처리).
- **폴더명**: 제목 없으면 `여행_YYYYMMDD_HHMM` 자동 부여(untitled 충돌 방지 — `_plan_dir()` 개선). 제목 입력 시 기존 리네임 로직이 폴더 리네임.

## 3. 컴포넌트

### 백엔드 (app.py)
- **`_save_project()`** — 위 스키마로 `<plan_dir>/project.json` 저장. 실패는 로그만.
- **`_load_project(folder)`** — `plans/<folder>/`의 plan.json+project.json을 state로 스왑(`group_states`는 비움 — drafts는 기존 파일 복원 훅이 처리), `_plan_dir` 세팅. 반환 bool.
- **자동 저장 훅**: ① 분석 완료(`api_analyze` task done 직전) ② `_save_plan()` 끝(편승) ③ 발행 성공 시.
- **`published_gis` 백엔드 이동**: `state["published_gis"]=set()`. `api_publish`가 body의 `gi`(신규 옵션 파라미터)를 성공 시 기록, `api_publish_all`은 성공 그룹 기록. `/api/status`에 `published_gis` 배열 노출 — 프론트 `publishedGis`는 이걸 미러링(재시작·전환에도 ✓ 유지).
- **라우트**:
  - `GET /api/projects` → `[{folder, trip_title, region, days, saved_at, has_drafts}]` (plans/ 스캔, plan.json 헤더만 읽음, 최근 저장순)
  - `POST /api/projects/open {folder}` → `_save_project()`(현재) → `_load_project(folder)` → `{ok, folder}`
  - `POST /api/projects/new` → `_save_project()` → 세션 state 클리어(photo/plan/drafts/naver/style/receipts/published/completed/_plan_dir) → `{ok}`
- **서버 시작 복원**: 기존 `_load_last_plan()`을 `_load_project(최근 폴더)` 호출로 확장(project.json 있으면 photo_results까지 복귀).

### 프론트 (static/index.html)
- 헤더(로고 옆): `<select id="projSel">`(현재 프로젝트 selected) + `＋ 새 여행` 버튼.
- 로드 시 `GET /api/projects`로 채움. 변경 시 `confirm("현재 작업은 자동 저장됩니다. 전환할까요?")` → `POST /api/projects/open` → **`location.reload()`** (프론트 전역 자연 초기화 — 기존 재진입 복원 경로 재사용).
- `＋ 새 여행`: confirm → `POST /api/projects/new` → reload → 업로드 스텝.
- `publishedGis`는 `/api/status`의 `published_gis`로 초기화(미러).

## 4. 에러 처리 · 불변식
- 저장/로드 실패는 경고 후 진행(전환 실패 시 현재 세션 유지 + alert).
- 전환은 **항상 저장 후 로드** — 데이터 유실 없음.
- `project.json`에 API 키·시크릿 미포함(설정은 settings.json/프로필 소관).
- 기존 라우트 계약 무변경(추가 필드만).
