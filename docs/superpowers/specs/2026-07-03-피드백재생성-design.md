## 2. 핵심 제약과 메커니즘 — "자산 잠금 revise"

**제약(실측)**: 가안 `post["content"]`는 ~1.7MB — base64 사진이 임베드돼 있어 LLM에 통째로 넘길 수 없다.

**메커니즘** ("형식은 코드가 조립, AI는 본문만" 불변식의 확장):
```
가안 content
 → _protect_assets(): 코드 조립물을 [KEEP_1]…[KEEP_n] 토큰으로 치환
    · <figure>…</figure> (base64 사진) — 필수 잠금
    · 지역 위키박스 <div style="background:#f7f8f3…">…</div> (내부 중첩 div 없음)
    · 이동경로 카드 (linear-gradient div — html_to_blocks의 기존 감지 정규식 재사용)
 → 경량 텍스트(수 KB) + 피드백 + 형식 규칙 → LLM revise (기존 self.client)
 → _restore_assets(): 토큰 → 원 자산 복원. 토큰 결손/중복 시 None(= revise 거부)
 → _number_places 재적용, seo_check 재계산
```
- AI가 사진·박스·카드를 물리적으로 만질 수 없음 → 삭제·변조 원천 차단
- revise 프롬프트 규칙: "피드백에 해당하는 부분만 수정, 나머지 문장은 그대로 유지. [KEEP_n] 토큰 절대 추가/삭제/이동 금지(순서 유지). 구글맵/경로/URL 삽입 금지."

## 3. 컴포넌트

- **`TravelBlogGenerator._protect_assets(content) -> (text, assets)`** — 순수함수. assets는 치환 순서의 원문 리스트.
- **`TravelBlogGenerator._restore_assets(text, assets) -> str | None`** — 모든 `[KEEP_i]`가 정확히 1회씩 존재해야 복원. 결손·중복·미지 토큰 → None.
- **`TravelBlogGenerator.revise_draft(post, feedback, naver_analysis=None) -> dict | None`** — protect → LLM → restore → `_number_places` → 새 post dict(content/tags 유지, seo_warnings 재계산) 반환. LLM 실패·복원 실패·빈 피드백 → None (원본 무손상).
- **`/api/revise` (POST `{gi, di, feedback}`)** — 백그라운드 스레드(+`/api/status` 폴링, 기존 관례). 성공: `state["group_states"][gi]["drafts"][di]` 갱신 + progress done. 실패: progress error `"재작성 실패 — 원본은 유지됩니다"`.
- **UI (`renderS4` 상단)** — "✍️ 피드백으로 다듬기" 카드: textarea + [최종본 재작성] 버튼. 클릭 시 `confirm("재작성하면 블록 수동 편집 내용이 초기화됩니다. 계속할까요?")` → `/api/revise` → 폴링 → done 시 블록 재로드(loadBlocks). error 시 alert. **반복 가능**(재작성본에 다시 피드백 가능).

## 4. 에러 처리 · 불변식

- 자산 결손/LLM 예외/JSON 아님 → revise 거부, **원본 그대로** + 에러 노출 (조용한 실패 금지).
- revise 결과도 기존 스크럽·URL 미누출 원칙 적용(코드 조립물이 잠겨 있으므로 새 URL이 들어올 표면 자체가 작음 — 프롬프트 금지 + 복원 후 `http` 신규 유입 검사).
- 빈 피드백 → 400 즉시 거부.
- 발행 흐름 무변경: revise는 drafts를 바꿀 뿐, blocks/발행 경로는 기존 그대로.
