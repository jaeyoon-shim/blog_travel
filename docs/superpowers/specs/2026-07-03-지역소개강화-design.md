# 지역소개(위키박스) 강화 + 표시 버그 2건 (F1) — 설계 문서

- 날짜: 2026-07-03
- 배경: 사용자 테스트 피드백 "처음 지역 소개 문구가 너무 빈약" + 최종 생성본 스크린샷에서 버그 2건 발견([[next-features-feedback]] F1)
- 상태: 설계 확정(사용자 F1 착수 지시) → writing-plans

## 1. 문제 3건과 원인

| # | 증상 | 원인 (확정) |
|---|---|---|
| a | 위키박스 빈약 — 일반론 intro 2문장 + 항목 2~3개 | `_generate_region_desc`(core.py:2090)가 **근거 자료 없이** 모델 내부 지식만 사용. 환각 방지("확실한 것만, 하한 없음")로 재료가 빈약한 지역은 텅 빔 |
| b | `## 📍 …` 마크다운 리터럴 노출 | `html_to_blocks`(posters.py:353-354)가 일반 `<h2>/<h3>`를 마크다운 `# `/`## ` **텍스트 블록**으로 변환 → `blocks_to_html`이 `<p>`로 감싸 복원 안 됨 |
| c | `PLACE N` 미채번 | 프롬프트 템플릿의 리터럴 `PLACE N`(core.py:2270)을 AI가 채번하지 않고 그대로 출력 |

## 2. 설계

### a. 위키박스 강화 — 실측 근거 주입 (환각 방지 원칙 유지)
- `_generate_region_desc(self, region_hint, naver_analysis=None)` 로 시그니처 확장.
- `naver_analysis`가 있으면 프롬프트에 실측 근거 추가:
  `[실측 참고 — 이 지역 검색 상위 블로그의 빈출 키워드/제목. 이 중 당신이 확실히 아는 것만 반영하고 모르는 것은 무시]` + `common_keywords` 상위 10 + `top_titles` 상위 5.
- intro 요구 2~4줄 → **3~5줄**, specialties/foods/spots 상한 각 0~4 → **0~6** (하한 금지·temperature=0·"지어내기 절대 금지"는 그대로 — lessons #3).
- `generate_drafts`가 이미 받는 `naver_analysis` 인자를 `_generate_region_desc` 호출에 전달.
- **자동 근거 확보**: `api_generate`/`api_generate_all`(app.py)에서 생성 시작 시 `state["naver_analysis"]`가 비어 있으면 plan region으로 SEO 분석을 자동 1회 실행(try/except, 실패 시 조용히 기존 방식 — 생성은 절대 안 죽음). 약 10~20초 추가.

### b. `##` 노출 수정 — 일반 h2/h3 → heading 블록
- `html_to_blocks`의 두 정규식(`<h2>→'# '`, `<h3>→'## '`)을 **heading 블록 생성**으로 교체(data-place h2가 이미 heading 블록으로 처리되는 기존 경로와 동일 패턴).
- `blocks_to_html`은 heading 렌더(`<h2 style=…>`) 기보유(app.py:161) → 미리보기/발행 모두 정상.
- 발행(NaverSeleniumPoster)의 heading 블록 처리 경로는 기존과 동일(추가 변경 없음).

### c. PLACE 채번 — 코드 후처리 (형식은 코드)
- 순수 staticmethod `_number_places(content)`: content에 나타나는 `>PLACE N<` 리터럴을 등장 순서대로 `>PLACE 1<`, `>PLACE 2<`…로 치환. AI가 이미 숫자로 채번했으면 무변경. LLM 없음.
- `generate_drafts`에서 post content 완성 직후 적용.

## 3. 에러 처리 · 불변식
- SEO 자동 분석 실패/미존재 → `naver_analysis=None` → 기존 프롬프트 그대로(품질만 기존 수준, 에러 아님).
- 실측 키워드는 **참고 재료**일 뿐 — "모르는 건 무시" 지시로 keyword-편승 환각 차단. 개수 하한 여전히 금지.
- 위키박스 HTML은 계속 **코드가 조립**(AI는 JSON 값만). b·c 모두 AI 의존을 줄이는 방향.

## 4. 테스트 (tests/test_quality.py 관례)
- `test_region_desc_uses_naver_evidence` — LLM monkeypatch, `naver_analysis` 전달 시 프롬프트(호출 kwargs)에 실측 키워드 포함 + 미전달 시 기존 프롬프트(회귀).
- `test_html_to_blocks_no_markdown_heading` — `<h3>제목</h3>` 포함 HTML → blocks에 `## ` 리터럴 부재 + heading 블록 존재.
- `test_number_places` — `PLACE N` 2회 → `PLACE 1`/`PLACE 2`; 이미 채번된 `PLACE 1`은 무변경; `PLACE N` 없음 → 무변경.

## 5. 변경 범위
- `core.py`: `_generate_region_desc` 시그니처·프롬프트, `generate_drafts` 호출 1줄 + `_number_places` 신규·적용.
- `posters.py`: `html_to_blocks` h2/h3 변환 2곳.
- `app.py`: `api_generate`/`api_generate_all` 자동 SEO 확보(각 ~5줄).
- `tests/test_quality.py`: 3개.
