# 테스트 피드백 개선 라운드 G1~G4·G6 — 설계 문서

- 날짜: 2026-07-03
- 배경: 사용자 실사용 테스트 피드백 5+1건. G5(공개 이미지 소싱)는 Wikimedia 기반으로 **다음 라운드 별도 설계**(JNTO japan.travel은 공식이나 오픈 라이선스 아님 — 자동 수집 부적합).
- 상태: 설계 승인 → writing-plans

## G1. 초안 영구 보존 (STEP4 저장하기)
- **문제**: state 인메모리 — 서버 재시작 시 생성 초안 소실.
- **설계**: 생성(`api_generate`/`api_generate_all`)·재작성(`api_revise`) 완료 시 `plans/<제목>/drafts/group_<gi>.json`에 **자동 저장**. STEP4에 [💾 초안 저장] 수동 버튼(`POST /api/drafts/save`). 재진입/재시작 후 STEP4·5 진입 시 state에 초안이 없고 저장 파일이 있으면 **자동 복원**(`_load_saved_drafts`) — 사진 재분석 없이 편집·발행 가능(이미지 원본은 uploads/에 존재).
- 저장 실패는 경고 로그만(생성 흐름 안 막음). photo_results 등 무거운 참조는 저장 시 제외 가능하나 blocks 변환에 photo path가 필요 → **post dict 그대로 저장**(photo_results 포함, 파일 크기 무해 — base64는 content에만).

## G2. 발행 후 다음 일차 흐름 (STEP6)
- **문제**: 단건 발행 후 다른 Day를 발행하려면 STEP5로 돌아가 그룹 전환 필요 — 흐름 끊김.
- **설계**: `renderS5` 상단에 **일차(그룹) 탭**(STEP5와 동일 스타일). 클릭 시 해당 그룹 blocks/제목/태그 로드 후 폼 갱신. 발행 완료된 일차는 ✓ 표시(프론트 `publishedGis` Set). 단건 발행 done 시 남은 일차 있으면 `confirm("다음 일차(N일차)를 발행할까요?")` → 자동 전환.

## G3. 인라인 블록 편집 (STEP5)
- **문제**: 블록 클릭 시 목록 **아래**에 작은 편집창 — 안 보이고 창이 작음.
- **설계**: 블록 아이템 클릭 시 **그 자리에서** 내용 영역이 textarea(min-height 120px)로 전환돼 즉시 수정(`editBlk` 재사용, input 시 미리보기 갱신). 하단 별도 편집 카드는 제거. 편집 불가 타입(image/separator)은 기존처럼 선택만.

## G4. 지역소개 확장 + 요청사항 강제 격상
- **a. 위키박스 확장**: JSON 스키마에 `tips`(💡 여행 팁 0~3), `access`(🚌 가는 법 0~2) 추가, intro 4~6줄, `max_tokens=900`. 환각 방지 유지(확실한 것만·하한 금지·실측 근거·temperature 0).
- **b. 지시 격상**: 현재 plan의 `ai_instruction`이 사건/느낌과 `" / "`로 합쳐져 `[사용자 메모]`로만 주입(core.py:1646→2206) — 비중 약함. **지시만 분리**해 `[장소별 필수 지시 — 아래 지시는 반드시 그대로 따르세요. 다른 규칙과 충돌하면 이 지시가 우선]` 섹션으로 격상. 사건/느낌은 기존 메모 유지. `TripPlanner`의 memo 조립에서 지시를 별도 dict(`place_directives`)로 분리 → `generate_drafts`→`_build_prompt`로 전달.

## G6. 제목 최적화 (노출 최우선 — 코드가 강제)
- **문제**: 제목이 AI 자유 생성이라 검색 노출에 약함("이상한 제목"). seo_check는 경고만.
- **설계**: `TravelBlogGenerator.optimize_title(post, naver_analysis, region) -> str|None`
  - 입력 근거: `top_titles`(상위 10 실측), `common_keywords`, `avg_title_length`, 글 요약(제목+본문 앞부분 텍스트).
  - LLM 1회(temperature 0.5, json_object): 상위 제목의 패턴(구조·키워드 배치·길이)을 모방해 **제목 후보 3개** 생성. 규칙: 지역명 필수 포함, 낚시·과장 금지, 본문 내용 기반.
  - **코드 검증·채택**: 후보 중 `지역명 포함 AND 15~45자` 첫 통과 후보 채택. 전부 탈락/LLM 실패 → 기존 제목 유지(seo_check 경고가 잡음).
  - `generate_drafts`에서 post 완성 시 `naver_analysis` 있으면 **항상 실행**(필수 내장). 원제목은 `post["original_title"]` 보관. 편집 화면 수동 수정은 그대로 가능.

## 에러 처리 · 불변식 (공통)
- 모든 신규 단계는 실패 시 기존 결과 유지(생성·발행 절대 안 죽음), 조용한 실패 금지(로그+가능하면 UI).

## 변경 범위
- `core.py`: `optimize_title` 신규, `_generate_region_desc` 스키마 확장, `TripPlanner` memo 분리(`place_directives`), `_build_prompt` 지시 섹션, `generate_drafts` 배선.
- `app.py`: drafts 저장/복원 헬퍼 + `/api/drafts/save` + 자동 저장 훅(generate/generate_all/revise) + `/api/status`에 `has_saved_drafts`.
- `static/index.html`: STEP4 저장 버튼, STEP5 인라인 편집, STEP6 일차 탭+다음 일차 흐름, 재진입 초안 자동 로드.
- `tests/test_quality.py`: 4~5개 (50 → 55 내외).
