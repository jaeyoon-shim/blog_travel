## 1. 문제 / 동기

현재 워크플로우는 사진 분석 직후 **사람이 개입할 틈 없이 바로 원고를 생성**한다.

```
1.업로드 → 2.구조 설정(모드만 선택) → 3.AI 생성 → 4.편집 → 5.발행
```

- 자동 추측한 장소명·지역이 자주 틀린다(특히 무료 모드: 일본어 원문 누출, 엉뚱한 동네). 사용자가 **생성 전에 고칠 방법이 없다.**
- 사용자가 가진 **풍부한 1차 정보**(무슨 일이 있었는지, 느낀 점, 별점, 실제 결제 금액)가 글에 반영될 통로가 없다. AI가 사진만 보고 추측해 살을 붙인다 → 빈약하거나 날조.
- 다회 여행/멀티데이 일정의 **날짜·장소 구성**을 사람이 손볼 수 없다.

## 2. 결정 (한 줄 요약)

> 사진 분석 후 **AI 생성 전에 "계획 검수" 단계**를 추가한다. 프로그램이 `Day → 장소 → 사진` 초안을 자동 생성하면, 사용자가 **장소명·일정 구성·사진 배치·핵심사건·느낀점·AI지시·별점·영수증(가격)** 을 확인·수정한다. 확정된 계획(`plan.json`)이 **생성의 단일 진실원**이 되며, 프로젝트 불변식 **"형식은 코드가 조립, AI는 본문만"** 을 그대로 따른다.

**핵심 데이터 흐름 변경:**
```
[지금]  분석 → (자동 추측을 생성기가 직접 읽음) → 생성
[변경]  분석 → 계획 초안(draft TripPlan) → ★검수·수정★ → 확정 TripPlan(plan.json) → 생성기는 오직 이것만 읽음
```

## 3. 데이터 모델 — `TripPlan` (plan.json)

생성기가 읽는 유일한 입력. 자동 추측과 사람 교정이 한 곳에 모인다.

```jsonc
{
  "plan_version": 1,
  "trip_title": "삿포로 3박4일",
  "region": "홋카이도",            // 위키박스/네이버검색(E) 키워드. 사람이 교정.
  "region_source": "user|auto|none",
  "free_mode": true,               // 무료 모드 여부(배너 표시용)
  "days": [
    {
      "day_no": 1,
      "date": "2026-06-22",        // null 가능(날짜 미상)
      "stops": [
        {
          "stop_id": "s1",
          "order": 1,
          "name": "오타루 운하",
          "name_source": "user|auto|none",   // none이면 비움(환각 방지)
          "events": ["운하 산책", "유리공예 거리 구경"],  // 핵심 사건(여러 줄)
          "feeling": "해질녘 가스등이 켜지는데 로맨틱했음",  // 느낀점/분위기
          "ai_instruction": "야경 중심, 차분한 톤",         // (선택) AI 작성 지시
          "rating": 4.5,            // null 가능. 0~5
          "receipt": {              // null 가능
            "image_path": "uploads/receipts/s1_xxx.jpg",
            "store_name": "小樽硝子",
            "amount": 2000,
            "currency": "JPY",      // ¥/₩/$ 자동 인식
            "date": "2026-06-22",
            "ocr_source": "auto|user"   // 사용자가 수정하면 user
          },
          "show_rating": true,      // 블로그 표시 토글(기본 true)
          "show_price": true,
          "photo_ids": ["p3", "p4", "p7"]   // 포함 사진(순서 유지)
        }
      ]
    }
  ],
  "undated_photo_ids": ["p20"],     // 날짜 미상 버킷
  "excluded_photo_ids": ["p9"]      // 어느 stop에도 없음(글에서 제외)
}
```

**사진 안정 ID**: 파일 경로/내용 해시 기반으로 `photo_id`를 부여해, 재분석해도 같은 사진 = 같은 ID가 유지되도록 한다(드래그/이동 상태 보존).

## 4. 컴포넌트

### ① 계획 초안 자동 생성 (`TripPlanner` — 신규, core.py)
분석 결과(`photo_results`)에서 draft `TripPlan`을 만든다. 기존 `TripStructurer`(이미 `by_day`/`by_place` 보유)를 재활용해 **Day → 장소** 2단계로 합성.

- **Day 분리**: EXIF 로컬 날짜 기준. **새벽 4시 이전 사진은 전날**로 귀속(컷오프 상수). EXIF 날짜 없는 사진 → `undated_photo_ids`.
- **장소 묶기**: 기존 `_group_by_place`(근접 GPS 묶음) 로직 재활용. 시간 간격 크면 같은 장소라도 별도 stop(재방문).
- **장소명**: `name_confident`(2026-06-19 스펙)일 때만 채우고, 불확실하면 `name=""`, `name_source="none"`(환각 방지 원칙 유지).
- **순수 함수로 분리**(테스트 대상):
  - `TripPlanner._assign_day(photo_dt, cutoff_hour=4) -> date|None`
  - `TripPlanner._build_draft(photo_results) -> dict`(네트워크 X)

### ② 영수증 OCR (`ReceiptReader` — 신규, core.py)
기존 `PhotoAnalyzer`의 OpenAI Vision 경로 재활용. 영수증 이미지 1장 → 구조화 추출.

- `read(image_path) -> {store_name, amount, currency, date}`(Vision 호출 1회).
- **항상 수정 가능**: OCR 결과는 stop.receipt에 채우되 `ocr_source="auto"`. 사용자가 고치면 `"user"`.
- **교차검증 제안(강제 X)**: `store_name`↔`stop.name`을 `_name_match`(기존)로 비교, 유사하면 "장소명에 반영?" 제안. `date`↔`day.date` 불일치면 "다른 날?" 제안.
- **금액 파싱 순수 함수**(테스트): `ReceiptReader._parse_amount(text) -> (amount:int, currency:str)` — `¥2,000`/`₩12,000`/`$15.00` 기호·천단위 처리.
- v1은 **장소당 영수증 1장**. 다중은 백로그.
- 영수증 이미지는 `uploads/receipts/`에 저장. **발행에서 절대 제외**(개인정보).

### ③ 검수 API (app.py 신규 라우트)
계획은 `state["plan"]`에 보관 + `plan.json` 영속화.

- `POST /api/plan/draft` — 분석 후 draft 생성(없을 때). 기존 plan 있으면 **덮어쓰기 확인 플래그** 요구.
- `GET  /api/plan` — 현재 plan 반환.
- `POST /api/plan` — plan 전체 저장(검수 화면 편집 결과). `plan.json` write.
- `POST /api/plan/stop/move` — 사진을 다른 stop/Day로 이동(`photo_id`, `to_stop_id`).
- `POST /api/plan/stop` — stop 추가(사진 0장 가능)/삭제/병합/순서변경.
- `POST /api/plan/receipt` — 영수증 업로드 → `ReceiptReader.read` → stop.receipt 채움.
- `POST /api/plan/exclude` — 사진 제외/복원.

### ④ 검수 화면 (index.html — `2. 계획 검수`)
기존 `2. 구조 설정` 단계를 대체. 모드 선택(by_place/by_course) 제거 — **Day→장소로 통일**(당일치기는 Day 1개).

- **무료 모드 배너**(상단): "무료 모드 — 상호명 정확도 낮음, 검수 권장"(백로그 #4 해결).
- Day 섹션 아코디언 → 장소 카드 목록. **장소 카드** 필드: 이름 / 핵심사건(줄 추가·삭제) / 느낌 / AI지시 / 별점(클릭) / 영수증(업로드→자동채움→수정) / 사진 썸네일.
- **사진 이동**: v1은 "Day N · 장소 X로 이동" 드롭다운/버튼(드래그앤드롭은 백로그). 제외 토글.
- "날짜 미상" 버킷 → 사용자가 Day로 배치.
- **[건너뛰고 생성]** 버튼: 초안 그대로 바로 3단계로(급할 때).
- 데스크톱 기준.

### ⑤ 생성 반영 (`TravelBlogGenerator`)
생성기가 `selected_groups`/자동 장소명 대신 **확정 `TripPlan`** 을 읽도록 입력 경로 변경.

| plan 입력 | 글에 들어가는 방식 |
|---|---|
| `stop.name`, `region` | **코드 조립**(위키박스·경로카드) — 자동값이 아닌 **사용자 확정값** 사용 |
| `rating`, `receipt.amount` | **코드 조립**: 그 장소 문단 끝에 `⭐4.5 / ¥2,000` 한 줄(토글 켠 stop만, 기본 표시) |
| `events`, `feeling`, `ai_instruction` | **AI 본문 재료**로 프롬프트 전달 → AI가 그 장소 문단을 문장화. 빈 칸은 AI가 사진·장소로 보완. |

- **안전장치**: `ai_instruction`은 톤·강조까지만. **시스템 규칙(구글맵/경로 HTML 금지 등)이 우선** — 사용자 지시로 형식 규칙을 못 깬다(프롬프트 시스템 메시지 + 결정적 스크럽 유지).
- 별점·가격 줄도 **코드가 HTML 조립**해 삽입(URL 없음, SE3 링크카드 변환 방지 원칙 유지).

## 5. E(네이버 구조)와의 연결점

후속 스펙 E는 본 스펙의 출력인 **확정 `region`(및 필요 시 `trip_title`)** 을 입력으로 받아 네이버 상위 10개 블로그 구조를 도출한다. 본 스펙은 **`region`을 확정·노출하는 책임까지만** 진다. E는 `region`이 비어있지 않음을 전제로 한다(비면 E는 조용히 생략).

## 9. 불변식 점검 (회귀 위험)

- "형식은 코드가 조립, AI는 본문만" — 별점·가격 줄, 위키박스, 경로카드 모두 코드 조립 유지. AI엔 재료(events/feeling/instruction)만.
- 구글맵 URL 본문 삽입 금지 — 별점·가격 줄에 URL 없음.
- 신뢰 기반 POI — draft에서 불확실 이름은 비움(`name_source="none"`), 사용자가 채움.
- 무료 모드 폴백 데이터 계약 — plan의 `region`/`date`가 무료 모드에서도 채워지는지(또는 비고 사용자 입력 유도하는지) 확인.
