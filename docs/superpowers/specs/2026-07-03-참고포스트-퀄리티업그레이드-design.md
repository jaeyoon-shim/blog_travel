# 참고 포스트 퀄리티 업그레이드 (I라운드) — 설계

날짜: 2026-07-03
참고: https://blog.naver.com/eng1470/224259142651 ("나래범" 기타큐슈 1일 코스 총정리, 공감 41·댓글 22)

## 배경 — 참고 포스트 구조 분석 (실측)

스마트에디터 컴포넌트 시퀀스를 실제 DOM에서 추출한 결과, 장소 섹션마다 정형 패턴이 반복된다:

```
se-horizontalLine (구분선)
→ se-text: "🏯 고쿠라 성" (이모지+장소명, 19px)
→ se-imageGroup (사진 2~10장 콜라주) + 캡션("고쿠라 성")
→ se-text: 본문 (개인 경험 + 실용정보: 가격 엔화·영업시간·"~한 사람에게 추천")
→ se-oglink (구글맵 장소 카드, ★평점·주소 표시, maps.app.goo.gl)
→ se-text: "↑↑ 위치 ↑↑" (가운데 정렬)
```

그 외 퀄리티 요소: 인트로에 코스 요약 한 줄(`고쿠라 역 → 호텔 → 카페 → 성 → 시장 → …`),
첫/끝 스티커, 관련 자기 글 내부 링크, 태그 24개 롱테일, 제목 `[지역 여행] 키워드 총정리 || 감성 부제`.

## 사용자 결정 (2026-07-03)

1. **구글맵 장소 OG 카드 도입** — 불변식 완화 승인:
   - 기존: "구글맵 URL을 HTML에 절대 넣지 않는다"
   - 변경: **"본문(텍스트 블록) 내 URL 금지"는 유지.** 단, 발행기가 **독립 블록**으로 URL을
     붙여 OG 카드 변환을 **의도적으로 유도**하는 것은 허용(참고 포스트의 핵심 퀄리티 요소).
   - AI 프롬프트의 "URL 금지" 규칙은 그대로(AI는 여전히 본문만).
2. 범위 = 핵심 세트: ① 사진 콜라주+캡션 ② 실용정보 프롬프트 ③ 인트로 코스 요약 ④ 태그 확장.
   내부 링크·스티커·위치첨부는 다음 라운드.

## 설계

### I1. 사진 콜라주 + 캡션 (코드 조립)

클립보드 발행은 이미지를 한 장씩 붙이므로 네이버 자체 imageGroup은 만들 수 없다.
→ **PIL로 코드가 콜라주 이미지를 합성**해 한 장으로 붙인다("형식은 코드가 조립" 원칙 그대로).

- `_compose_collage(paths) -> tmp_path`: 같은 장소 사진들을 2장 단위(마지막 홀수 1장은 단독)로
  가로 결합. 높이 정규화(예: 1080px) 후 가로 이어붙임, 사이 여백 8px 흰색. EXIF 방향 보정 필수
  (`ImageOps.exif_transpose`, `_photo_html`과 동일). 품질 85 JPEG.
- 그룹핑 소스는 기존 `_insert_photos_with_map`의 `place_groups`(location_name 기준) 재사용.
  같은 장소 사진 ≥2장일 때만 콜라주, 1장은 현행 유지.
- **캡션**: 콜라주(또는 단독 사진) 바로 아래 가운데 정렬 회색 작은 글씨로 장소명
  (기존 📍 라인 스타일 재사용, 참고 포스트의 캡션과 동일한 시각 효과).
  네이버 에디터 실제 캡션 필드 자동화는 DOM 리스크가 커서 이번 범위 제외.
- 미리보기 HTML(`_photo_html`)도 콜라주 이미지를 쓰므로 미리보기=발행 결과 일치.

### I2. 구글맵 장소 OG 카드

- **place_id 보존**: `_resolve_poi`(구글 모드)에서 채택된 POI의 `place_id`를 photo_result에
  `place_id` 필드로 저장. (현재는 이름만 저장하고 버림.)
- **URL 생성**: `https://www.google.com/maps/place/?q=place_id:<ID>` (리치 OG 카드 유도).
  무료 모드/place_id 없음 → **현행 📍 텍스트 폴백** (조용한 생략 원칙 유지).
- **블록 계약**: `_photo_html`이 장소 마지막 사진 뒤에 마커 주석
  `<!--MAPCARD:<url>:<display>-->`를 삽입 → `html_to_blocks`가 이를
  `{"type":"map_card","url":...,"label":"↑↑ <display> 위치 ↑↑"}` 블록으로 변환.
  미리보기 HTML에는 카드 대신 현행 📍 라인 표시(URL 미노출 유지).
- **발행기**: `_paste_map_card(url, label)` — URL을 단독 문단으로 붙여넣고 Enter →
  에디터의 oglink 변환 대기(`.se-oglink` 출현 폴링, 최대 ~8초) → 변환 실패 시
  붙인 URL 문단을 삭제(Ctrl+A 아님 — Shift+Home 선택 삭제)하고 📍 텍스트 폴백 →
  성공 시 다음 줄에 "↑↑ 위치 ↑↑" 가운데 정렬 텍스트.
- **리스크**: 네이버 DOM 타이밍. 실발행(비공개) E2E로 검증하고, 실패해도 발행 자체는
  계속되도록(카드=부가 요소) 방어적으로 작성.

### I3. 본문 실용정보 밀도 + 추천 대상 (프롬프트)

`TravelBlogGenerator` 프롬프트에 참고 포스트 패턴 반영:

- 장소 소개마다 "이런 사람에게 추천" 문장 1개 (예: "혼자 여행하는 사람들에게도 괜찮을 것 같았다").
- 가격·영업시간 등 실용정보는 **주어진 근거(영수증 데이터, plan의 사건/느낌, 실측 SEO 참고)가
  있을 때만** 서술. 근거 없으면 쓰지 않는다 — **개수·항목 강요 금지** (환각 교훈 lessons #3).
- 짧은 단락 리듬(2~4문장 단위 줄바꿈), 경험담(1인칭 감상) → 실용정보 → 추천 순 흐름.

### I4. 인트로 코스 요약 한 줄 (코드 조립)

- `_insert_course_summary(content, plan)`: plan의 stop 순서로
  `A → B → C → D` 한 줄을 인트로 첫 `<h2>` 직전(또는 위키박스 뒤)에 코드가 삽입.
  가운데 정렬, 장소명 텍스트만(URL 없음). stop 8개 초과 시 주요 stop만(사진 수 상위).
- AI에게 맡기지 않는다(순서 왜곡·환각 방지).

### I5. 태그 확장 (결정적 코드 생성)

- `merge_tags` cap 10 → **25**.
- `_expand_tags(region, place_types)`: 지역명 × 방문 카테고리 조합을 결정적으로 생성
  (`{지역}여행`, `{지역}여행코스`, `{지역}맛집`, `{지역}카페`, `{지역}가볼만한곳`,
  `{지역}숙소`…). 카테고리는 실제 방문 stop의 scene/POI 타입에서만 도출(방문 안 한
  카테고리 태그 금지). 기존 `extract_core_tags`(실측 빈도) 우선, 조합은 후순위 채움.

## 불변식 갱신

- CLAUDE.md 핵심 설계 원칙 2번을 다음으로 개정:
  "**본문 텍스트에 구글맵 URL을 넣지 않는다.** 지도 카드는 발행기가 독립 블록으로 URL을
  붙여 OG 카드 변환을 의도적으로 유도한다(`map_card` 블록). AI 프롬프트의 URL 금지는 유지."

## 검증

- 유닛: `_compose_collage`(크기·방향), 마커→`map_card` 블록 변환, `_expand_tags`,
  `_insert_course_summary`(순서·8개 초과 축약), 프롬프트에 URL 금지 규칙 잔존 확인.
- E2E: 실생성(콜라주·코스요약·태그 확인) + **실발행(비공개)**으로 OG 카드 변환 확인.
