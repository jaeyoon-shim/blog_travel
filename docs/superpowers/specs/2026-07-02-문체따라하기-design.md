# 문체 따라하기 (Style Mimicry) — 설계 문서

- 날짜: 2026-07-02
- 로드맵 위치: **B. 문체 따라하기** (sub-project, [[plan-review-feature-roadmap]])
- 상태: 설계 확정 대기 → 승인 시 writing-plans로 구현계획

## 1. 배경 · 목적

참고 블로그 URL의 문체를 분석해 생성 원고에 이식하는 기능은 **기초 수준으로 이미 작동 중**이다:
`참고 URL → /api/style → StyleAnalyzer.analyze() → state["style_analysis"] → 생성 시 _style_context로 프롬프트 주입`.

그러나 현재 방식엔 세 가지 약점이 있다:

1. **정규식 휴리스틱이 거침** — `_detect_tone`(3분류)/`_detect_endings`가 정규식이라 부정확. 어미가 파편(`보람.`)으로 잡히고, 리듬·화자·이모지 습관 같은 진짜 문체 특징을 못 잡는다.
2. **원문 통째 주입 위험** — `_style_context`가 참고글 문단을 그대로 프롬프트에 넣어 AI가 문장을 복붙할 수 있다(표절 리스크).
3. **(부수) 스크래핑 신뢰성** — 네이버 블로그는 본문이 iframe/동적이라 BeautifulSoup으로 충분히 안 긁힐 수 있다.

로드맵의 권장 방향(2026-06-30 브레인스토밍): **"원문 통째 주입 대신 문체 특성 추출 → 규칙 + 예시"**.

### 목적 (이번 범위)
- (b) 정규식 휴리스틱 → **LLM 기반 문체 프로파일 추출**로 교체(폴백은 유지).
- (c) 원문 통째 주입 → **규칙 JSON + 짧은 대표 예시 문장**으로 전환(표절 방지).
- (a) 모방 정확도는 위 두 개선의 결과로 따라온다.
- (d) 스크래핑 실패는 이번 범위에선 **엔진 교체 없이**, "텍스트 부족 시 사용자에게 경고"로만 다룬다.

### 기존 요청 대조 (누락 없음 확인)
로드맵 B 항목("참고 링크 few-shot 문체 모방 / StyleAnalyzer·api/style 기반 존재 / 특성추출→규칙+예시")의 모든 항목을 본 설계가 반영한다:
- 참고 링크로 모방 → `/api/style` 유지·강화
- few-shot → 규칙 + 대표 예시 문장 1~2개(문단 통째 아님)로 정신 계승
- 특성추출→규칙+예시 → 접근법 A의 핵심
- 기존 기반 활용 → 교체 아닌 **확장**

## 2. 접근법 결정

| 접근 | 요약 | 채택 |
|---|---|---|
| **A. LLM 문체 프로파일 추출** | 스크래핑 원문 → LLM 1회 → 규칙 JSON → 규칙+예시로 프롬프트 조립 | ✅ 채택 |
| B. 정규식/휴리스틱 강화 | LLM 없이 분류·통계 개선 | ✗ 여전히 얕음, 로드맵 목표 미달 |
| C. Few-shot 원문 주입 | 원문 문단을 few-shot으로 | ✗ 표절 위험 잔존 |

**채택: A.** 로드맵 방향과 일치, 목적 (a)(b)(c) 동시 해결. 비용은 문체 분석 시 작은 LLM 호출 1회(캐시되어 URL 셋이 바뀔 때만 재실행). 기존 OpenAI 클라이언트 재사용.

## 3. 아키텍처

`StyleAnalyzer`를 2단계로 확장: **① 스크래핑(기존 유지)** → **② LLM 문체 프로파일 추출(신규)**. 결과 규칙 JSON을 `state["style_profile"]`에 캐시. 생성 시 `TravelBlogGenerator._style_context`가 규칙+예시로 프롬프트 조각을 조립.

```
참고 URL ─▶ StyleAnalyzer.analyze(url) ─┬─ _scrape(url): 원문 문단/제목 (기존 로직)
                                        └─ extract_profile(원문): LLM 1회 → 규칙 JSON
                                                    │
              state["style_profile"] ◀─────────────┘  (URL 셋 바뀔 때만 재추출)
                                                    │
              generate ─▶ _style_context(profile) ─▶ [참고 문체] 프롬프트 조각
```

## 4. 컴포넌트 (경계 · 책임)

- **`StyleAnalyzer.__init__(config=None)`** — config 주입(선택). 없으면 정규식 폴백 전용.
- **`StyleAnalyzer._scrape(url) -> dict`** — 기존 `analyze`의 스크래핑부를 분리. 원문 문단/제목/이미지수 수집. 순수 I/O, LLM 없음.
- **`StyleAnalyzer.extract_profile(text, headings) -> dict`** (신규) — LLM 호출로 규칙 JSON 생성. config 없거나 무효(무료모드)면 기존 정규식(`_detect_tone`/`_detect_endings`)으로 최소 프로파일 반환.
- **`StyleAnalyzer.analyze(url) -> dict`** (개선) — `_scrape` → `extract_profile` 조립. 텍스트 부족 시 `warning` 필드 세팅.
- **`TravelBlogGenerator._style_context(profile) -> str`** (개선) — 규칙 JSON → 프롬프트 조각. **순수함수, 네트워크 없음**(유닛테스트 대상). 원문 문단 통째 금지, 예시 문장 1~2개 상한.

## 5. 데이터 모델 — `style_profile` JSON

```json
{
  "tone": "친근 구어체 + 반말 섞임",
  "sentence_length": "짧고 끊어치는 리듬, 감탄사로 시작",
  "ending_patterns": ["~더라고요", "~었어요"],
  "emoji_usage": "ㅎㅎ 가볍게 문단당 1회 정도",
  "rhetorical_habits": ["감탄으로 도입", "'근데'로 화제 전환", "생활어 사용"],
  "person": "1인칭 혼잣말체",
  "dos": ["솔직한 리액션 먼저, 정보는 뒤에"],
  "donts": ["격식체(습니다) 금지"],
  "examples": ["아 이거지 싶더라고요", "기다린 보람 있었어요!"],
  "source_urls": ["..."],
  "extracted_by": "llm",
  "warning": null
}
```
- 모든 리스트는 `0~N개, 확실한 것만, 없으면 빈 배열` (환각 방지, lessons-learned #3).
- 추출 LLM 호출은 `temperature=0`, `response_format={"type":"json_object"}` (기존 TripPlanner 패턴 재사용).
- `extracted_by`: `"llm"` | `"regex_fallback"`.

### 프롬프트 조각 형태 (규칙 + 예시)
```
[참고 문체 — 아래 규칙을 모방하되 문장을 그대로 베끼지 말 것]
· 톤: 친근 구어체, 반말 섞임 / 1인칭 혼잣말
· 리듬: 짧게 끊고 감탄사로 시작
· 어미: ~더라고요 / ~었어요
· 이모지: ㅎㅎ 가볍게 문단당 1회
· 습관: '근데'로 도입·전환, 생활어 사용
· 참고 어감(복붙 금지): "아 이거지 싶더라고요"
```

## 6. 데이터 흐름 (예시)

참고 원문 → `extract_profile` → 규칙 JSON → `_style_context` → 프롬프트 → 생성 원고.
결과: **어미·리듬·화제전환·이모지 습관은 이식되되, 원문 문장은 복붙되지 않고** 사용자 실제 사진 내용으로 작성됨.

## 7. 에러 처리 · 불변식

- **키 없음/무효(무료 모드)**: `extract_profile`가 정규식 폴백 → `extracted_by:"regex_fallback"`. 파이프라인 안 죽음.
- **스크래핑 실패/텍스트 부족(#4)**: 수집 텍스트 < 임계치(200자)면 프로파일을 조용히 만들지 않고 `warning` 세팅 → `/api/style` 응답에 포함 → UI에 노출. (무료모드 가시성 교훈: 조용한 품질저하 금지)
- **LLM JSON 파싱 실패**: 폴백으로 강등 + 로그 경고. 생성은 계속.
- **불변식(형식은 코드, AI는 본문만)**: 이 기능은 **본문 텍스트 문체에만** 관여. `_style_context`는 구글맵/경로/위키박스 HTML을 절대 생성·언급하지 않는다(본문 톤 규칙만).
- **표절 방지 불변식**: 프롬프트 예시는 문장 1~2개 상한, 원문 문단 통째 주입 금지.

## 8. 테스트 (순수함수 분리 → monkeypatch, 네트워크 없음)

`tests/test_quality.py` 관례:
- `test_style_context_from_profile` — 규칙 JSON → 프롬프트 조각. 어미/톤/예시 포함 + **원문 문단 통째 미포함**(표절 방지 회귀).
- `test_extract_profile_regex_fallback` — config=None → 정규식 폴백, `extracted_by=="regex_fallback"`.
- `test_extract_profile_llm` — `client.chat.completions.create` monkeypatch로 가짜 JSON → 파싱·정규화 검증.
- `test_thin_text_warning` — 텍스트 200자 미만 → `warning` 세팅, 프로파일 미생성.
- `test_style_context_empty` — profile 없음/빈 값 → 빈 문자열(생성 무영향).

## 9. 변경 범위 (파일)

- `core.py`: `StyleAnalyzer.__init__(config=None)`, `_scrape` 분리, `extract_profile` 신규, `analyze` 개선, `_style_context` 개선.
- `app.py`: `/api/style`에서 `StyleAnalyzer(engine.config)` 전달 + `warning` 응답 필드. `state`에 `style_profile` 추가.
- `static/index.html`: `doStyle()` 성공 시 `warning` 있으면 표시, 추출된 문체 요약 간단 노출(선택).
- `tests/test_quality.py`: 위 5개 테스트.
