# 사람 참여 기획·중간 보정 (브리프 → 목차 승인 → 본문 → 섹션 보정) — 설계

- 날짜: 2026-10-19
- 상태: 설계 승인됨 (사용자 결정 4건 반영), 구현 계획 전
- 관련: `docs/reviews/2026-10-19-기획-기능-UXUI-종합점검.md` (U11·U15 저장 경계, P7 "검수 노동" 로드맵)

## 1. 목적

사람이 **처음부터 글 기획에 참여**하고, AI가 쓰는 **중간중간 보정**할 수 있게 한다.

현재(실측): 장소 단위 조종(사건·느낌·장소별 지시·사진 구성)은 프롬프트에 "반드시 반영"으로 충실히 들어간다. 그러나
- 글 단위 방향(컨셉·독자·핵심 메시지)을 정하는 입력이 없다.
- 본문을 한 번에 전부 생성 — 쓰기 전 볼 수 있는 목차 단계가 없다.
- 제목은 `optimize_title`(core.py:3971)이 후보 중 하나를 조용히 골라 사용자 제목을 덮는다(core.py:2181-2184).
- 사후 보정은 글 전체 재작성(`revise_draft`)과 메모리 전용 블록 편집(새로고침 시 소실)뿐. 섹션 단위 재작성·고정 없음.

## 2. 사용자 결정 (2026-10-19)

| 질문 | 결정 |
|---|---|
| 개입 방식 | **브리프 → 목차 승인 → 본문**, 본문은 섹션별 다시 쓰기·고정 |
| 브리프 단위 | **여행 공통 + 일차별 보충** (빈칸은 공통 값 상속) |
| 목차 편집 범위 | **내용만 편집, 섹션 순서 고정**(방문 순서). 순서 변경은 계획 검수에서 |
| 제목 | **목차에서 후보 제시 → 사람이 확정**. 확정 제목은 절대 덮어쓰지 않음 |
| 구현 방식 | **A: 2단 생성** (목차 호출 1회 추가 + 기존 본문 파이프라인 재사용) |

범위 밖: 섹션 순서 변경, 테마별 섹션, 대화형 기획, 장소 안 대표 사진 지정, 초안 다중 비교.

## 3. 데이터 모델

### 3.1 브리프 — `plan.json`

```json
{
  "brief": {
    "concept": "부모님 모시고 간 느긋한 온천 여행",
    "reader": "50~60대 부모님과 여행을 계획하는 30대",
    "message": "무리하지 않는 동선이 효도 여행의 핵심",
    "must_include": "휠체어/계단 정보, 대기 시간",
    "avoid": "과장된 맛 표현"
  },
  "days": [
    { "...기존 필드": "...",
      "brief": { "message": "", "must_include": "", "avoid": "" } }
  ]
}
```

- 모든 필드는 선택. 빈 문자열 = 미지정.
- 일차 brief의 빈칸은 공통 brief 값을 상속 — 순수함수 `merge_brief(trip_brief, day_brief) -> dict`.
- 기존 plan 자동저장(`/api/plan` POST, 디바운스 `savePlan`)을 그대로 탄다. `collectPlan`이 brief 필드를 수집하도록 확장.
- `TripPlanner.merge_user_edits`(재초안)가 `brief`·`days[i].brief`를 보존해야 한다(사용자 확정이 진실원).

### 3.2 목차 — `plans/<title>/drafts/outline_<gi>.json`

```json
{
  "title_candidates": [{"title": "...", "has_keyword": true}],
  "title": "사용자가 확정한 제목 (없으면 \"\")",
  "intro_hook": "인트로 첫 문단 방향 1~2문장",
  "sections": [
    {"place": "연화의湯", "gist": "섹션 요지", "emphasis": "강조점", "length": "보통"}
  ],
  "tips": ["꿀팁1", "꿀팁2"],
  "outro": "아웃트로 방향 1문장",
  "approved": false,
  "brief_used": { "...병합된 브리프 스냅샷": "" }
}
```

- `sections[].place`는 그룹의 장소 목록(재방문 접미 포함)과 **같은 순서·같은 이름**이어야 한다. 서버가 저장 시 검증하고, AI 응답의 장소 누락·추가·순서 뒤바뀜은 코드가 그룹 장소 순서로 정규화(누락 섹션은 빈 요지로 채움, 미지 장소는 버림).
- `length` ∈ {짧게, 보통, 길게}. 그 밖의 값은 "보통".
- 저장 위치가 `drafts/` 안이므로 `/api/plan/draft`(새 계획 = 새 원고 세션)가 drafts 폴더를 지울 때 함께 지워진다 — 의도된 동작(계획이 바뀌면 목차의 장소 목록이 무효).
- gi ↔ 일차 대응: `groups_from_plan`은 `plan.days` 순서대로 그룹을 만든다. 일차 brief 조회는 그룹에 `day_index`를 실어 명시적으로 한다(빈 일차가 생겨도 어긋나지 않게).

### 3.3 섹션 고정·블록 편집 — 초안(post) dict 확장

- `post["locked_sections"]: list[str]` — 고정된 섹션 키(`"__intro__"`, 장소명, `"__tips__"`).
- `post["edited_blocks"]: list | null` — 서버에 저장된 블록 편집 결과. 있으면 `/api/blocks`가 이것을 반환하고 발행·미리보기가 사용.
- **post 스키마 확장 시 소비 관문 3곳 점검**(lessons 07-02 #5): `generate_drafts` → `/api/drafts` 화이트리스트 직렬화 → 프론트. `_save_drafts`는 dict 통째 저장이라 무변경.

## 4. 흐름과 화면

### 4.1 1단계 준비 — 여행 공통 브리프
업로드 영역 옆(또는 아래)에 접히지 않는 카드 "이 여행 이야기" 5칸. 분석 전에도 입력 가능해야 하므로 plan이 아직 없으면 `state["pending_brief"]`에 보관하고 `/api/plan/draft` 시 plan에 옮긴다. 입력은 디바운스 자동저장 + `_save_project()` 훅(lessons 07-04 #2).

### 4.2 2단계 계획 검수 — 일차별 보충
각 일차 카드 상단에 3칸(핵심 메시지·꼭 넣을 것·빼고 싶은 것), placeholder로 공통 값 표시("비우면: …"). 기존 `#planRoot` delegated 자동저장 범위 안에 둔다.

### 4.3 3단계 원고 — 목차 화면 (초안이 없는 일차의 첫 화면)
1. **"목차 만들기"** → `POST /api/outline/<gi>` (백그라운드 + `/api/status` 폴링, 기존 패턴).
2. 목차 편집 카드:
   - 제목 후보 3개(라디오, 키워드 포함 배지) + 직접 입력 → 확정
   - 인트로 훅(textarea)
   - 장소 섹션 목록(순서 고정, 번호 표시): 요지·강조점(input), 분량(셀렉트)
   - 꿀팁(줄 단위 textarea), 아웃트로(input)
   - 편집은 디바운스 자동저장 `PUT /api/outline/<gi>`
3. **"이 목차로 본문 쓰기"** → `outline.approved=true` 저장 후 기존 `/api/generate` 호출(`use_outline: true`).
4. **"목차 없이 바로 쓰기"** — 현재 방식 그대로(탈출구, 기존 초안과 호환).

초안이 이미 있는 일차는 지금처럼 편집 화면이 열리고, "목차 보기/수정" 버튼으로 목차 화면에 갈 수 있다.

### 4.4 3단계 원고 — 섹션 보정
편집 화면의 미리보기(또는 블록 목록)를 섹션 단위로 묶어 각 섹션 머리에 툴바:
- **✏️ 다시 쓰기**: 지시 입력 → `POST /api/revise_section` → 해당 섹션만 교체.
- **📌 고정 / 해제**: `locked_sections` 토글(즉시 저장).
- 상단 **"목차대로 다시 쓰기"**: 목차를 반영해 전체 재생성하되, 고정 섹션은 이전 초안의 해당 섹션 HTML로 되붙임.
- 블록 직접 편집: 변경 시 `PUT /api/blocks/<gi>/<di>`로 `edited_blocks` 저장(디바운스) + "저장됨/저장 중" 표시 + 미저장 시 `beforeunload` 경고.
- 섹션 재작성·전체 재생성은 본문 HTML을 바꾸므로 `edited_blocks`를 무효화한다 → 실행 전 confirm("직접 고친 블록 편집이 초기화됩니다").

## 6. 불변식·안전장치

1. **형식은 코드가 조립, AI는 본문만** — 목차는 텍스트 요지만 다룬다. 지도·경로·사진·위키박스는 섹션 재작성에서도 KEEP 토큰으로 잠근다.
2. **본문 텍스트에 URL 금지** — 섹션 재작성 결과에 신규 `https?://`가 있으면 거부(data URI 제외 후 검사, lessons 08-17(2) #7).
3. **방문 순서 = 섹션 순서 = 사진 순서** — 목차 정규화가 순서를 강제, 본문 생성 이후의 사진 배치(LIS·`data-files`)는 무변경.
4. **실패를 성공으로 승격 금지** — 목차 생성 실패는 `status:error` + 메시지("목차 생성 실패 — 다시 시도하거나 '목차 없이 바로 쓰기'"), 섹션 재작성 실패는 원본 유지 + 사유 표시.
5. **사용자 확정 우선** — 확정 제목, 고정 섹션, 브리프, 목차 편집은 어떤 재생성도 조용히 덮지 않는다.
6. **동시 실행** — 목차 생성·섹션 재작성도 기존 생성과 같은 상태(`state["progress"]`)를 쓰므로, 진행 중이면 버튼 비활성화(전역 락 F4는 별건이지만 이 기능의 신규 라우트는 진행 중 409를 반환).

## 7. 비용

- 목차: 일차당 입력 ≈ 장소 목록 + 브리프 + 메모(사진 base64 없음) → 소형 호출 1회.
- 섹션 재작성: 섹션 텍스트(자산은 토큰) 크기만큼 — 전체 `revise_draft`보다 작다.
- 본문 생성 호출 수는 변화 없음.

## 8. 테스트

순수함수(`tests/test_quality.py` 관례, 네트워크 없음):
- `merge_brief` 상속/덮어쓰기, 빈 브리프 → 빈 조각
- `normalize_outline`: 장소 누락·추가·역순·미지 length·후보 5개 → 정규화
- `outline_prompt_block`/`brief_prompt_block`에 `{`·`}` 포함 사용자 텍스트 → 프롬프트 빌드 시 예외 없음

- `splice_locked`: 고정 섹션 보존, 없는 키 무시
- `revise_section`: KEEP 결손/중복/신규 URL/length 잘림 → 원본 유지 (AI 스텁)
- 확정 제목 → `optimize_title` 미호출 (스텁으로 호출 여부 assert)
- `merge_user_edits`가 brief 보존

라우트(test_client, AI 스텁, `_plan_dir` tmp, 스레드 동기화):
- outline 생성→PUT 편집→GET 왕복, 재시작 시뮬레이션(state 비우고 GET) 후에도 존재
- `use_outline` 생성 시 프롬프트에 승인 목차 조각 포함
- `PUT /api/blocks` → `/api/blocks` GET이 `edited_blocks` 반환
- 진행 중 409

E2E(실 OpenAI, 저장 경로 안 타는 직접 호출, lessons 08-17 #6):
- 1일차 목차 생성 → 요지 1개 수정·제목 확정 → 본문 생성 **2회**: 제목 보존, 수정한 요지가 해당 섹션에 반영, figure alt 시퀀스 == EXIF 순서, 첫 h2 이전 figure 0, 본문 URL 0
- 섹션 1개 재작성 + 다른 섹션 고정 후 전체 재생성: 고정 섹션 HTML 바이트 동일

UI: `node vm.Script` 파싱 + `/browse`로 1~3단계 렌더·콘솔 에러 0·스크린샷 육안 확인(lessons 08-17(3) #7).

## 9. 구현 순서(제안)

1. 순수함수 + 테스트 (브리프 병합, 목차 정규화·조각, 섹션 분할·이식)
2. 브리프 저장(plan 스키마·`collectPlan`·`merge_user_edits`·pending_brief) + 1·2단계 UI
3. 목차 생성·저장 라우트 + 3단계 목차 화면 + `use_outline` 생성 + 제목 확정
4. 섹션 재작성·고정 + 편집 화면 툴바
5. 블록 편집 서버 저장 + 미저장 표시
6. E2E·실렌더 검증, WORKFLOW.md 갱신
