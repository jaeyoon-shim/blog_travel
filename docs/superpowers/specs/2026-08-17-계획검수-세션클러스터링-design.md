# 계획검수 장소 묶기 — 세션 클러스터링 설계

날짜: 2026-08-17
상태: 구현·검증 완료 (`b2af99b`, `85b9f9b`)
⚠ **사후 기록** — 관례상 착수 전에 남겨야 하나, 이번엔 대화에서 결정하고 바로 구현했다.
결정 근거·기각안이 코드에 남지 않아 여기 복원해 둔다.

## 배경 — 측정이 우선순위를 뒤집었다

핸드오프의 최우선 잔여는 "`place_groups`가 location_name 키로 **비연속 재방문을 병합**한다"였다.
착수 전 실데이터를 재보니:

- `plan.json`의 stop 시간구간 **교차 0건** — 그 결함은 현재 데이터에서 발생하지 않는다.
- 본문 섹션 구조를 정하는 층은 GPS `location_name`이 **아니라 plan stop**이다
  (`groups_from_plan`이 stop 이름으로 `location_name`을 덮어쓴다).
- 그대로 "연속 run 단위 그룹핑"을 구현했다면 3일차 섹션이 6개 → **49개로 폭발**할 뻔했다.

대신 데이터가 가리킨 진짜 결함은 **자동 stop 과분할**이었다.

| 일차 | 사진 | 자동 stop(구) | 사용자가 손으로 정리한 결과 |
|---|---|---|---|
| 3일차 | 62장 | **31개** | 6개 |
| 2일차 | 34장 | 20개 | 8개 |
| 1일차 | 6장 | 5개 | 3개 |

원인: `_stops_for_day`가 '확신 이름 키 + ~110m 격자'라, 무료 모드 역지오코딩 세부명이
같은 장소 안에서 관광지/공원/거리/신사/주차장으로 갈리고 격자 경계까지 겹쳤다.

## 결정

**시간·거리 세션 클러스터링** — 시간순으로 훑으며 직전 사진과 (시간차 ≤ 45분 AND 거리 ≤ 300m)이면
같은 stop. "사람이 한 장소라고 부르는 것 = 그 자리에 머무는 동안의 연속 촬영"이라는 관찰에 기반하고,
**이름 품질에 의존하지 않아 무료 모드에서 특히 강하다.**

### 임계값 근거 (사용자 확정 stop = 정답 레이블)

사진 쌍 기준 P/R/F1로 그리드서치. 과병합 = 사용자 '분리' 노동, 과분할 = '합치기' 노동.

| 방식 | 평균 F1 |
|---|---|
| 이름키 + 110m 격자 (구) | 0.456 |
| 세션 45분 / 300m (채택) | **0.940** |
| 세션 30분 / 300m | 0.908 |
| 세션 45분 / 200m | 0.815 |
| 세션 45분 / 500m | 0.797 |

거리는 300m에 뚜렷한 봉우리, 시간은 30~60분 고원이라 45분 채택.

### 기각안

- **v2: 세션 + "확신 POI 이름이 바뀌면 경계"** — 직관적이지만 F1 **0.841**로 오히려 하락.
  무료 모드에선 `name_confident`가 대부분 False이고, 확신 이름이 붙은 개별 건물명
  (`船屋形`, `浣心亭`)이 같은 장소 안에서 바뀌며 과분할을 만든다.
- **연속 run 단위 그룹핑(원래 백로그)** — 위 배경대로 섹션 폭발. 기각.

## 계약 변경 — 재방문 분리

세션 클러스터링은 같은 이름의 **다른 방문**을 별개 stop으로 만든다. 하류가 전부 `name` 키로
묶으므로(`place_groups`, 프롬프트 장소목록, `memos`/`meta` dict) 그대로 두면 한 섹션으로
재병합되고 메모·별점·지시가 서로를 덮어썼다.

- **사이에 다른 장소가 낀 동명 stop = 재방문** → `이름 (재방문)`으로 구분.
- **연속된 동명 stop은 재방문이 아니다** — 한 장소가 잘게 쪼개진 것이라 접미를 붙이면
  헛 "(재방문)" 섹션이 생긴다(실데이터 재초안에서 발견).
- `merge_user_edits`는 사용자가 손댄 구 stop을 재초안이 다시 쪼개면 **되붙인다**
  (사용자 확정이 진실원). 손대지 않은 자동 stop이면 새 알고리즘 결과를 유지.

옛 계약("확신 이름이 같으면 시간·거리 무관 병합")을 못 박던 테스트 2건은 새 계약으로 갱신했다.

## 알려진 한계

45분·300m로는 **인접한 두 장소**를 못 가른다(6일차 중 유일한 과병합: 기타노 이진칸 ↔ 고베 거리 구경).
사용자가 ✂분리 1회로 해결 가능. 더 줄이려면 체류 밀도·방향 전환 같은 신호가 필요하다.
