## 2. 코드 리뷰 (변경별)

### 2.1 `.env` — Google Maps 키 비활성화
- **정확성:** ✅ `config.json`에 google 키 없음 → `.env`가 유일 소스. 주석 처리로 무료화 즉시 발효. 검증됨(`Config().get("google","maps_api_key") == ""`).
- **설계:** 기존 "키 truthiness = 기능 토글" 관용구를 따름. 코드가 모든 경로에서 Nominatim 폴백/생략을 안전 처리.
- **🟡 우려:** 무료 모드가 **암묵적**이다. `.env`를 열어보지 않으면 앱이 무료 모드인지 알 수 없다. 명시적 플래그/상태 표시 부재.

### 2.2 `_fetch_place_detail` — Places 가드
- **정확성:** ✅ `nearby = {}` 초기화 + `if key:` 래핑. 다운스트림 `if nearby.get("results")`가 빈 dict를 안전 처리. 대규모 재들여쓰기 없이 최소 변경.
- **🟡 관찰:** 순수 무료 모드(google 키 X + naver client_id/secret X)에서는 이 메서드가 **항상 ""를 반환**한다 → 사실상 dead call. 동작엔 문제없으나 낭비.

### 2.3 `_nominatim_geocode` — city/region/country (환각 버그 수정)
- **근본 원인 해결:** ✅ 호출부(`:646-648`)가 `addr_data["city"/"region"/"country"]`를 읽는데 Nominatim이 이를 반환하지 않아 무료 모드에서 항상 빈 값 → `_detect_region`이 messy 장소명을 region으로 넘김 → GPT가 "홋카이도 삿포로" 환각. 이제 `city='기타큐슈시', region='후쿠오카현'` 정상.
- **계약 일관성:** ✅ `_google_geocode`(`:903`)도 동일한 `city/region` 키를 반환 → 유료/무료 경로 계약 일치.
- **🟡 사소한 비대칭:** `_google_geocode`는 `country`를 안 채우는데 Nominatim은 채운다. 호출부가 `.get("country","")`라 무해하나 두 경로가 미묘하게 다름.
- **🟡 의미 느슨:** `city` 폴백에 `county`(군) 포함 — 행정구역 레벨이 city와 다를 수 있음. 현재 데이터셋엔 문제없음.

### 2.4 연속 구분선 정규화
- **정확성:** ✅ AI가 인접 구분선 2개를 출력하는 경미 버그를 최종 조립 지점에서 1개로 정규화. 재생성 후 5/5 중복 0.
- **🟡 견고성:** HTML을 정규식으로 처리. 중첩 수량자(`(?:\s*(?:<br>)?\s*(?:SEP))+`)는 입력이 작아 실무상 안전하나, 정규식-on-HTML은 본질적으로 깨지기 쉬움.
- **🟡 위치:** `_insert_photos_with_map` 한 곳에만 적용. 이 경로가 유일 chokepoint라 현재는 충분하나, 다른 조립 경로 생기면 누락 위험.

## 3. 10년차 매니저 관점 평가

**총평: 변경은 외과적(surgical)이고 정확하다. 근본 원인을 짚었고(환각=빈 region) 검증도 했다. 다만 "수정"에서 멈췄고 "재발 방지"가 약하다.**

### 🔴 P1 — 테스트 부채 (가장 중요)
이번에 추가한 로직(Nominatim city/region, 구분선 정규화)에 **커밋된 유닛테스트가 0개**다. 이 프로젝트는 `tests/test_quality.py`라는 "순수 로직 유닛테스트" 관례가 이미 있고, 구분선 정규화는 **네트워크 없이 1줄 입력→출력으로 검증 가능**한 전형적 케이스다. `_gen_test.py`는 일회용 E2E 스크립트일 뿐 회귀 가드가 아니다.
> 환각 버그가 다음 리팩터에서 조용히 재발할 수 있다. EM이라면 머지 조건으로 테스트를 요구한다.

### 🔴 P1 — 위키 박스 환각은 INPUT만 고쳐졌다
region을 정확히 넘기게 했지만, 위키 박스는 여전히 **GPT에게 사실을 자유 생성**시킨다. 재생성본에서도 "다카마쓰 공원"(시코쿠 소재) 같은 인접지 혼입이 남아 있다. `"확실한 사실만"` 프롬프트는 약한 가드다. 무료 모드는 입력 품질이 낮아 garbage-in을 증폭한다.
> 결정 필요: (a) 발행 전 검수 전제로 수용, (b) 주요 여행지 큐레이션 사전, (c) specialties/spots 제거하고 intro만 유지.

### 🟡 P2 — 무료 모드 품질 저하가 사용자에게 비가시적
장소명 직역 거칢(`魚町`→"어촌", `小倉北区`→"쿠라키타 구")이 조용히 발생한다. 문서상 트레이드오프지만, 최종 사용자는 "정확도 낮음, 검수 필요"를 모른 채 발행하게 된다.
> UI/로그에 "무료 모드: 상호명 정확도 낮음" 배지/경고를 노출 권장.

### 🟡 P2 — 무료 모드가 암묵적 (운영성)
`.env` 주석으로만 제어. 명시적 `GOOGLE_MAPS_ENABLED` 같은 설정이나 기동 로그 배너가 없어, 협업자가 상태를 파악하기 어렵다.

### 🟢 P3 — 임시 산출물 위생
`_gen_test.py`, `_test_cache/`가 repo 루트에 있고 `.gitignore` 미등록. 커밋 오염 위험.

### 🟢 P3 — Windows 콘솔 인코딩 취약성 (기존 이슈, 범위 외)
cp949 콘솔에서 이모지 로그가 크래시(`UnicodeEncodeError`). 로깅 핸들러에 `errors="replace"` 미적용. 앱 디버깅을 어렵게 함. 이번 변경 원인 아님.

## 5. 코드 단순화 검토

### 이번 변경 자체
- **구분선 정규식 과설계(소):** `<br>` 분기는 불필요할 수 있다. `re.sub(r'(?:<p[^>]*>[\s─]*</p>\s*){2,}', canonical, content)`로 단순화 가능. **단, 동작 검증된 코드이므로 지금 건드릴 가치는 낮음.**
- **`_fetch_place_detail` dead call(소):** 순수 무료 모드에서 항상 ""반환. 메서드 진입부에서 `if not self.google_key and not naver_creds: return ""` 조기 반환 가능. 우선순위 낮음.

### 큰 그림 (이번 작업 범위 밖 — 별도 트래킹 권장)
- **"이 장소의 이름은 무엇인가" 책임이 5개 메서드에 분산:** `_nominatim_geocode` / `_google_geocode` / `_make_place_name` / `_translate_to_korean` / `_koreanize_region` / `_detect_region`이 서로 겹치는 책임을 가진다. 이름 해석(name resolution)을 하나의 응집된 단위로 통합하면 환각·번역 버그의 단일 수정점이 생긴다.
- **`core.py` 2,600+줄 단일 파일, God-class 2개**(`PhotoAnalyzer`, `TravelBlogGenerator`): 누적 중. 분리 후보 = 지오코딩/이름해석, 위키박스, 경로, 프롬프트빌드.

> **결론(단순화):** 이번 변경은 외과적이고 정확하므로 **지금 대규모 단순화는 권장하지 않는다**(리스크 > 이득). 대신 위 "큰 그림" 항목을 `lessons-learned`/리팩터 백로그로 트래킹하고, AI를 풀기 전 `/refactor-audit`을 한 번 돌리는 것을 권장.
